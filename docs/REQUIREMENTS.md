## 背景与范围

用户希望在独立仓库认真重做旧版 CustomThree 封装，并先建立工程资产。主包 npm 名称已确认为 `@adui/three`。预期使用者是开发 Three.js 场景的应用开发者；具体行业、规模和消费框架尚未确认。

本轮范围：审查当前模板与旧实现，建立需求、架构、设计、上下文、代码导航、Skills 索引和可执行文档校验。保留现有模板代码；本轮不实现库功能、不发布 npm、不迁移旧业务。

## 建议 MVP（待决策，非已批准需求）

建议第一阶段只做场景宿主、相机/渲染器、可选 OrbitControls、统一帧循环、容器 resize、资源释放和一个最小演示。第二阶段再选模型加载、拾取、DOM 标签；后处理、寻路、漫游、GIS、编辑器和框架适配按真实需求推进。

建议验收场景：同页两个实例互不干扰；重复 start 不叠加循环；停止后不渲染；容器零尺寸无 NaN；重复 dispose 安全；销毁后异步加载结果不回挂；共享资源不被误释放。以上需在实现时分配正式编号与测试。

## 非功能与安全边界

性能指标需先确定设备、模型规模、分辨率和基准场景，不编造 FPS、内存阈值。可靠性重点为生命周期、异常回滚、资源和事件清理。模型 URL、鉴权和 CORS 由应用及资产服务管理；客户端环境变量不作为保密机制。暂不需要数据库、后端认证、生产基础设施或遥测服务，未来按实际需求补充。
